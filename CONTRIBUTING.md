# Правила участия (Contribution Guidelines)

Спасибо, что хочешь помочь с проектом **shark24**! Вот как лучше всего внести вклад.

## Как предложить изменения

**Обязательно следуй этим шагам:**

1. Сделай **форк репозитория** (кнопка *Fork* вверху справа).
2. Создай новую ветку с понятным именем, например:
   ```bash
   feature/добавить-меню
   fix/исправить-баг
   ```
3. Внеси изменения и сделай коммит. Пиши сообщение кратко на русском или английском: что именно ты сделал.
4. Отправь **Pull Request** в основной репозиторий.

## Что писать в коммитах

Старайся, чтобы было понятно без заглядывания в код.

**Хорошие примеры:**
- `добавил экран главного меню`
- `исправил вылет при переходе на уровень 3`
- `обновил README с инструкцией запуска`

**Избегай:** «обновил файлы», «фикс», «мелкие правки» — такие сообщения ничего не объясняют.

## Если нашёл баг

Открой **Issue** и напиши:

- Что должно происходить.
- Что происходит вместо этого.
- На каком устройстве/ОС ты запускал.
- Если есть ошибка в консоли — скопируй текст ошибки.

> Чем подробнее шаги для воспроизведения, тем быстрее получится исправить баг.

## Чего лучше не делать

- Не удаляй рабочие части проекта без обсуждения.
- Не добавляй кучу файлов, которые не относятся к проекту (картинки, документы, логи).
- Не отправляй Pull Request с незавершённой работой (если только специально не помечаешь его как *Draft*).

## Куда обращаться, если не уверен

Сначала открой **Issue** или напиши комментарий к Pull Request. Можно также написать в обсуждение проекта.

**Важно:** если ты делаешь крупное изменение, сначала согласуй идею в Issue. Это сэкономит время и тебе, и остальным.

# Contribution Guidelines

Thanks for wanting to help with the **shark24** project! Here’s the best way to contribute.

## How to propose changes

**Please follow these steps:**

1. Fork the repository (click the *Fork* button in the top right).
2. Create a new branch with a clear name, for example:
   ```bash
   feature/add-main-menu
   fix/fix-level-3-crash
   ```
3. Make your changes and commit them. Write a short message in English or Russian describing exactly what you did.
4. Open a **Pull Request** to the main repository.

## What to write in commits

Make it understandable without looking at the code.

**Good examples:**
- `added main menu screen`
- `fixed crash when transitioning to level 3`
- `updated README with launch instructions`

**Avoid:** `updated files`, `fix`, `minor tweaks` — these messages don’t explain anything.

## If you found a bug

Open an **Issue** and include:

- What should happen.
- What actually happens instead.
- The device/OS you’re using.
- If there’s a console error, copy the error text.

> The more detailed the reproduction steps, the faster we can fix the bug.

## Things to avoid

- Do not delete working parts of the project without discussion.
- Do not add unrelated files (images, documents, logs).
- Do not submit a Pull Request with incomplete work (unless marked as *Draft*).

## Where to ask if you’re unsure

Start with an **Issue**, or leave a comment on a Pull Request. You can also post in the project discussions.

**Important:** if you’re planning a major change, please discuss the idea in an Issue first. This saves time for everyone.
